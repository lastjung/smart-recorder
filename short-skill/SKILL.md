# 🎬 YouTube Shorts Automation Skill

본 스킬은 유튜브 숏츠(Shorts) 영상을 자동으로 기획하고 제작하는 표준 절차를 정의합니다.

## 0. 프로젝트 구조 (Project Structure)

- **위치**: 모든 프로젝트는 `tube/` 디렉토리 하위에 새로운 폴더를 생성하여 진행한다.
- **명명 규칙**: `tube/[주제_키워드_소문자]` (예: `tube/trump_retro_funny`)
- **표준 폴더 구조**:
  ```text
  tube/
  └── [project_name]/
      ├── assets/           # 다운로드한 원본 소스 (영상, 이미지, BGM)
      ├── voice_assets/     # 생성된 TTS 오디오 파일들
      ├── veo/              # Veo 영상 생성용 프롬프트 및 결과물
      ├── story.md          # 영상 기획안 및 스크립트
      ├── subtitles.srt     # 자막 파일
      ├── download_assets.sh # 리소스 다운로드 스크립트
      ├── gen_tts.py        # TTS 생성 파이썬 스크립트
      ├── build_short.sh    # FFmpeg 최종 합성 스크립트
      └── [final_output].mp4 # 최종 완성된 영상
  ```

## 1. 주제 및 용도 설정

- **방침**: 사용자(주인)에게 **영상 용도(유튜브 숏츠 또는 롱폼)**와 **주제**를 확인한다. 의견이 없을 시 웹 트렌드를 분석하여 임의로 선정한다.
- **추천 주제 예시**:
  - **Funny & Grumpy Cat**: 엉뚱하거나 심술궃은 고양이의 귀여운 사고뭉치 영상.
  - **Satire & Parody**: 트럼프 스타일의 보스, 고전 무성영화 등을 활용한 풍자 코미디.
  - **Animals & Friends**: 강아지와 아기, 고양이와 오리 등 이종 동물 간의 따뜻한 우정.
  - **Visual & Healing**: 비오는 창가, K-Pop 네온 시티, 밀밭의 평화로운 풍경 (Veo 활용).
  - **Unexpected Chaos**: 평화로운 일상에서 벌어지는 반전 코미디 (예: 햄스터의 탈출).
- **결정**: 유튜브 숏츠 (YouTube Shorts)

## 2. 동영상 소스 탐색

- **탐색 방식**: 작업을 시작할 때 반드시 **새로운 별도 윈도우(New Window)**를 열어 사용자 창과 격리한다. 모든 탭은 이 전용 윈도우 내부에서만 관리한다.
- **수량 확보**: 50초 숏츠 영상 제작을 위해, **최종 분량의 1.5배 이상 (최소 5~10개 클립, 총 80초 이상)**의 소스를 충분히 확보하여 편집 유연성을 높인다.
- **종료 방식 (절대 안전 원칙)**:
  1. **Page ID 대조**: 자신이 생성한 고유 Page ID 목록과 일치하는 탭만 선별하여 종료한다.
  2. **정밀 타격**: 광역 종료 명령어(`pkill`, `close all windows`)는 절대 금지한다.
  3. **사용자 보호**: 본인이 열었는지 확실치 않은 탭이나 윈도우는 절대로 건드리지 않고 사용자에게 확인을 요청한다.

- **활성 탭 제한 (엄격 준수)**:
  1. **최대 3개 제한**: 브라우저 내 활성 탭은 **최대 3개**까지만 허용한다.
  2. **즉시 정리**: 목적 달성(다운로드 완료) 혹은 무효 페이지(404, 차단 등) 확인 시 즉시 해당 탭을 종료한다.
  3. **순차 진행**: 탭이 3개를 초과할 경우, 새로운 탭을 열기 전 반드시 기존 탭을 우선 정리한다.

- **사전 승인 사이트**: 아래 목록의 사이트들은 작업 시 별도의 허락 없이 즉시 오픈하여 탐색할 수 있다. (단, 종료 규칙 준수)
  - _고전/빈티지_: **Archive.org, Pond5 Public Domain, Prelinger Archives**
  - _현대/시네마틱_: **Pexels, Pixabay, Mixkit, Coverr**
- **상태**: 허락없이 자동 진행한다

## 3. 음악 및 음성(오디오) 탐색

- **방침**: **영상의 테마, 리듬, 감성에 완벽하게 어울리는** BGM, 효과음(SFX) 또는 AI 나레이션을 확보한다. 음악이 영상의 분위기를 주도하고 완성도를 결정하므로 심혈을 기울여 선정한다.
- **사전 승인 사이트**: 아래 음악/음향 사이트들은 별도의 허락 없이 즉시 오픈하여 탐색할 수 있다. (단, 탭 제한 및 종료 규칙 준수)
  - **Pixabay Music, Mixkit (Audio/SFX), Free Music Archive (FMA), Bensound**
- **상태**: 허락없이 자동 진행한다

## 4. 제목 및 스크립트 제작

- **방침**:
  1. **스크립트**: 시청자의 시선을 끌 수 있는 제목과 영상 내 텍스트/자막을 구성한다.
     - **대화식 권장**: 단조로운 독백보다는 **2인 이상의 캐릭터가 서로 티키타카(Dialogue)하는 방식**을 적극적으로 사용한다. 연기 톤과 성별을 다르게 설정하여 몰입감을 높인다.
  2. **나레이션 (TTS)**: **Edge-TTS** 또는 **Google TTS** 방식을 사용하여 자연스러운 음성(`mp3`)을 확보한다.
     - **다양한 목소리**: 캐릭터별로 악센트(en-GB, en-US 등)를 다르게 주거나 FFmpeg의 `asetrate` 필터를 활용하여 **남자 목소리, 개성 있는 목소리 등으로 변조**하여 사용한다.
     - **권장 보이스**:
       - `en-US-RogerNeural`: 권위적이고 낮은 보스 목소리.
       - `en-US-GuyNeural`: 에너지 넘치고 쾌활한 목소리.
  3. **자막**: 나레이션과 싱크를 맞춘 `.srt` 파일을 생성하고, FFmpeg를 사용하여 영상에 **Hardsub(영구 자막)** 형태로 삽입한다.
- **상태**: 허락없이 자동 진행한다

## 5. 영상 합성 및 최종 편집

- **방침**: FFmpeg을 활용하여 최종 해상도로 합성한다.
- **영상파일**: 모든 영상 파일은 인위적로 반복, 속도조절등으로 시간을 늘리지 않는다.
- **오디오파일**: 모든 오디오 파일은 인위적로 반복, 속도조절등으로 시간을 늘리지 않는다.
- **오디오합성**: 배경음악(BGM)은 나레이션을 방해하지 않도록 Volume 0.1~0.3 수준으로 낮추고(Ducking), 나레이션은 Dynamic Normalization을 적용하여 명료하게 만든다.
- **파일제목**: 모든 영상 및 소리의 파일제목은 내용과 일치하게 붙인다. short_final.mp4 같은 일반적인 파일제목은 절대 사용하지 않는다.
  - **레이아웃 규격 (Layout Specs)**:
    - **메인 영상**: 상단 **80% (Top 1024px)** 영역을 사용한다. (720x1024)
    - **영상 처리**: 원본 영상을 **Center Crop**하여 빈 공간 없이 꽉 채운다. (옆면 잘림 허용)
    - **자막 영역**: 하단 **20% (Bottom 256px)** 및 영상 일부를 포함하여 여유롭게 사용한다.
  - **제목 (Title)**:
    - 위치: 상단 여백 (**MarginV=100**)
    - 색상: **Sky Blue (하늘색, &H00FFFF00)**
    - 크기: **Fontsize 40** (단위: Pixels)
  - **자막 (Subtitle)**:
    - 위치: 하단 완전히 밀착 (**MarginV=45**) - _조금 더 내림_
    - 색상: **Yellow (노란색, &H0000FFFF)**
    - 스타일: **BorderStyle=1 (Outline)**, No Box.
- **상태**: 허락없이 자동 진행한다

## 6. Log 기록 (지속성 및 무결성 유지)

- **로그 파일**: `tube/process_log.md`
- **기록 방식 (Append Only)**: 새로운 프로젝트나 단계가 시작될 때, **절대로 기존 내용을 지우거나 덮어쓰지 않는다.**
- **필수 포함 정보**: 작업 날짜와 시간(Timestamp)을 반드시 기재하고, 사용한 파일들 출처를 명시한다
- 문서의 **맨 아래(최하단)**에 이어서 추가한다.
- **결과 보고**: 제작의 성공/실패 여부를 명시하고, 실패 시 구체적인 사유를 기록한다.
- **상태**: 허락없이 자동 진행한다

## 7. 기술 참조 (Technical Reference)

**1. Pexels API**

- **비용**: 무료 (Free). 단, 시간당 요청 제한(Rate Limit)이 있음.
- **Key 발급**: Pexels 웹사이트 가입 후 무료 발급 가능.
- **사용법**: Header에 인증 키를 포함하여 요청.
  ```bash
  curl -H "Authorization: YOUR_API_KEY" "https://api.pexels.com/videos/search?query=nature..."
  ```

## 8. veo 동영상 의뢰 (AI Video Generation)

- **방침**: 고품질 AI 영상 생성을 위해 Google Veo를 활용 요청한다.
- **프로세스**:
  1. **스틸컷 준비**: 영상의 핵심 분위기를 담은 스틸컷 3장을 선정하여 준비한다 (Download + nanobanana 사용).
  2. **프롬프트 작성**: Veo가 이해할 수 있는 상세한 프롬프트 텍스트 파일을 생성한다.
     - **세분화 규칙**: 이미지별로 개별 프롬프트(`prompt_image1.txt`)를 작성한다.
  3. **저장 위치**: 프로젝트 내 `veo` 서브폴더를 생성하여 이미지 3장과 프롬프트 파일을 함께 저장한다.
  4. **요청**: 준비가 완료되면 주인(사용자)에게 Veo 생성을 요청한다.
- **상태**: 준비 후 사용자 승인 요청.

## 9. 파일 관리 및 명명 규칙 (IMPORTANT)

- **방침**: 모든 소스 파일(영상, 이미지, 오디오)은 다운로드 즉시 **내용을 명확히 식별할 수 있는 이름**으로 변경하여 저장한다.
- **금지**: `video1.mp4`, `image03.jpg`, `12345.mp3` 등 내용을 유추할 수 없는 무의미한 파일명 사용을 엄격히 금지한다.
- **실행**: 다운로드 스크립트(`download_assets.sh`) 작성 시, `output` 옵션을 사용하여 처음부터 의미 있는 이름을 부여하거나, 다운로드 직후 `mv` 명령어로 즉시 수정한다.
